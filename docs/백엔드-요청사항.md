# 백엔드 요청사항 — 코스 공유 토큰

코스 공유 링크를 붙이면서 막힌 두 가지입니다. 1번이 우선입니다.

작성: 2026-08-12 / 프론트 조영찬

---

## 1. 공유 토큰을 저장 응답 말고도 내려주기 ⭐️

### 지금 상황

`shareToken`은 **`POST /api/v1/courses`(저장) 응답에만** 실립니다.
`GET /api/v1/courses/{courseId}`(상세)와 `GET /api/v1/courses`(목록)에는
**필드는 있는데 값이 항상 `null`** 입니다.

### 문제

저장하는 그 순간 토큰을 못 받으면 **그 코스는 영영 공유할 수 없습니다.**
앱을 지웠다 다시 깔거나 기기를 바꾸면 이전 코스는 전부 공유 불가입니다.

### 지금 버티는 방법

저장 응답에서 받은 토큰을 **기기 로컬(Keychain)에 직접 적어두고** 있습니다.
(`ShareTokenStore` — `courseId → shareToken` 맵)

서버가 값을 채워주면 이 저장소는 지웁니다.

### 요청

```
GET /api/v1/courses/{courseId}
GET /api/v1/courses
```

→ 응답의 `shareToken`에 **실제 값 채워주기** (필드는 이미 있습니다)

## 2. 저장 없이 공유 토큰만 발급하는 API

### 지금 상황

코스 추천 결과 화면(담기 전)에서 공유를 누르면
**"먼저 내 코스에 담아주세요"** 안내만 띄우고 있습니다.

### 문제

사용자 입장에서 "공유하려면 왜 먼저 담아야 하지?"가 자연스럽지 않습니다.
담기는 날짜 선택까지 거쳐야 해서, 그냥 친구에게 보여주고 싶은 사람에게는
단계가 과합니다.

### 요청

```
POST /api/v1/courses/share
```

- 요청: 코스 데이터 (저장 API와 같은 payload)
- 응답: `{ shareToken }`
- **내 코스 목록에는 담기지 않고**, 공유 링크로만 열람 가능

> 1번만 해결돼도 "담은 코스 공유"는 정상 동작합니다.
> **담기 전 공유**까지 풀려면 2번이 필요합니다.

## 참고 — 확인된 것

- `GET /api/v1/public/courses/{shareToken}` 정상 동작
  (없는 토큰에 `ITINERARY-008` / "없는 공유 링크입니다" 응답 확인)
- 공유 웹페이지 배포 완료 — `https://offway.cloud/c/{shareToken}`
